# Deployment

Target: [Render](https://render.com) (free tier) using the blueprint [`render.yaml`](../render.yaml): two web services
(`pdm-hub-dev`, `pdm-hub-prod`) built from the `Dockerfile`, each with its own PostgreSQL database. Any container host works the same way.

## One-time setup

1. Render &rarr; *New* &rarr; *Blueprint* &rarr; select this repository. Auto-deploy is off on purpose; GitHub Actions triggers deploys.
2. For each service copy its **Deploy Hook URL** (Settings).
3. In GitHub &rarr; Settings &rarr; Environments create **dev** and **production** (add *required reviewers* to production).
   * secret `DEV_DEPLOY_HOOK_URL` and variable `DEV_URL` in **dev**
   * secret `PROD_DEPLOY_HOOK_URL` and variable `PROD_URL` in **production**
4. Production `ADMIN_TOKEN` is generated by Render (keep it private). Fault injection is off there.

## Flow

| Event | Result |
|---|---|
| Pull request | `ci.yml`: tests (SQLite, PostgreSQL), frontend tests, compose smoke test |
| Merge to `main` | CI &rarr; automatic deploy to **dev** &rarr; `scripts/smoke_test.py` against dev |
| Actions &rarr; *Deploy to production* (manual) | CI &rarr; reviewer approval &rarr; deploy hook &rarr; smoke test against prod |

## Rollback

Run *Deploy to production* again with `ref` = the previous known-good tag or SHA. Application-level bad configuration is rolled back
automatically by the on-call agent ([oncall-agent.md](oncall-agent.md)) or manually: `POST /admin/config/risk_model/rollback`.

## Running the alerter and the on-call agent in the cloud

They are included in `docker-compose.yml`. On Render they need two background workers (paid plan): start commands
`python -m oncall.alerter` and `python -m oncall.responder` with `HUB_URL`, `ADMIN_TOKEN`, `WEBHOOK_SECRET`, `RESPONDER_URL`.
